# Pub Quiz Scoring System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A native Linux Electron app with Launcher, Admin and Leaderboard windows, persisted quiz state, rules overlay, and a slideshow-style question presentation.

**Architecture:** Electron main process owns state (pure reducer in `src/shared/logic.js`), persists JSON atomically to userData, and broadcasts changes over IPC to all windows. Renderers are plain HTML/CSS/JS.

**Tech Stack:** Electron, vanilla JS, `node --test`, electron-builder (AppImage), inkscape for rasterising the default icon.

**Spec:** `docs/superpowers/specs/2026-10-02-pubquiz-design.md`

## Global Constraints
- Default title exactly "Pub Quiz Night"; default background `#1a1b4b` (all identity is configurable via branding).
- `contextIsolation: true`, `nodeIntegration: false`; no network dependencies at runtime.
- Exactly 4 options (A-D) per question; presentation sequence `[board, Q text, Q+options, board, ...]`.
- Persist to `userData/quiz.json` atomically; backup to `userData/backups/` before destructive actions.

## Review Focus
- Score input empty/negative/non-numeric/above max: rejected or cleared, never NaN.
- Removing a team/round/question while the presentation step points past the end: step clamps.
- Corrupt or missing `quiz.json` on startup: falls back to defaults (and keeps a copy of the bad file).
- Tied totals: equal rank, stable ordering; zero teams and zero rounds render without errors.
- Loading a JSON file of the wrong shape: rejected with a message, state untouched.
